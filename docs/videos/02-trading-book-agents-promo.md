## 판정: 채택할 것 없음
- **샤프 8.21·MDD 0.91% 는 실전 수치로 보기 어렵다.** 최상위 펀드도 샤프 2~3. 종목 3개뿐이고, 짧은 시험 기간·LLM 의 학습 데이터 누출(시험 기간 결과를 이미 알고 있을 가능성) 문제를 배제할 수 없다. 그래서 우리는 과거 재현이 아니라 **앞으로 나오는 판정만** 채점한다(Phase 1).
- **영상 속 실제 매매가 90배 방식의 결과를 보여준다.** 한 번 손절에 포지션의 27~38%. 1번 영상에서 기각한 방식과 같다. 우리 코드는 ATTACK·스캘핑 데스크를 없앴고 레버리지 1배를 `exchange.js` 에서 잠갔다.
- **구조는 이미 운영 중이다.** 뉴스(NOVA)·심리(VIBE) 분석이 있다. 논문의 "AI vs 규칙 기반(MACD·RSI·SMA)" 비교는 우리 AI vs H1/H2/M0 비교와 같은 틀이고, 우리 쪽이 전진 검증이라 더 엄격하다.
- **커뮤니티 데이터 추가는 보류.** 시험 중 입력을 바꾸면 표본이 섞인다. 10/13 성적표 이후 검토.

## 후속 — 판매자 배포 파일 검토 (2026-10-03, build 20261001zh)

오너가 영상 제작자 측 배포본(Windows 실행 파일 묶음)을 전달. **설치·키 연결 금지** 판정.

- **핵심 코드는 열지 않았다.** `server.js` 는 로더일 뿐이고 실제 서버 코드는 `core.dat` 에 AES-256-GCM 으로 암호화돼 있다. 열쇠는 판매자 서버(`/floor/key`)가 기기 식별값·버전을 받고 내준다. 동봉 README 가 보호조치 우회를 금지(저작권법 제104조의2)하므로 복호화 시도는 하지 않았다. 평문 파일(실행 스크립트·UI·차트·투어·README)만 검토.
- **안전 판정 — 실행하지 않는다.** 매매 핵심이 감사 불가능하고, 실행마다 외부 서버로 기기 식별값을 보내며, 판매자가 코드를 언제든 바꿀 수 있다. 거래소 키를 맡길 수 없다.
- **사업 구조:** 정식 기능은 "오렌지엑스 UID 활성화" 회원에게만 열린다(체험은 BTC·하루 5회). 거래소 추천인 수수료 모델로 판단 — 영상 1 분석과 같은 결론.
- **보이는 매매 규칙(UI 기준):** 손절은 "설정했을 때만"·자동매매 기본 손절 0, 2·3·4차 분할 추가 진입(평단 낮추기), 익절 +10% 고정·평단 갱신 시 재설정, 레버리지 배수·"청산선 도달" 알림, 2·3·4차 자동 주문 옵션. 우리 철칙(손절 필수·1배·추가 진입 없음·기대값 게이트)과 정반대이며, 손절 없는 물타기는 승률은 높아 보이나 한 번의 큰 역행으로 계좌가 끝난다.
- **채택 후보(아이디어만, 우리 코드로 새로 작성):** "관망 시 진입 자리 감시" — 관망 판정의 조건 가격(예: "2,807 돌파 시")을 위·아래 레벨로 걸고, 닿으면 재분석, 6시간 뒤 자동 해제. `analysis-budget.js` 에 이미 비어 있는 `level` 종류가 이 용도다. **10/13 성적표 이후** 검토(시험 중 표본 혼입 방지).
